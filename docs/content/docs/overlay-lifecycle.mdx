# Overlay lifecycle

Dialog, Popover, Tooltip, HoverCard, Menu, Drawer, AlertDialog, and CommandPalette share a **lifecycle contract** so you can style enter/exit in CSS and distinguish why an overlay opened or closed.

These `data-*` attributes and `--var-ui-*` variables are public API (same semver rules as class names). Recipes already animate from them; you can target the same hooks in your own CSS.

Helpers live on `@var-ui/react`:

```ts
import {
  useOverlayPresence,
  usePositionerVars,
  createOverlayChangeDetails,
  type OverlayOpenChangeHandler,
} from '@var-ui/react';
```

Compound overlays already call these. Use the hooks directly only if you are building a custom overlay on React Aria.

Stacking and themed portals are in [Getting started](/docs/getting-started).

## State attributes

Spread on the popup (and backdrop, when there is one). Presence is an empty string when set, omitted when not.

| Attribute             | Meaning                                                               |
| --------------------- | --------------------------------------------------------------------- |
| `data-open`           | Present while open, including during the exit animation until unmount |
| `data-closed`         | Present during the closing phase                                      |
| `data-starting-style` | Present for two animation frames after open (the enter “from” state)  |
| `data-ending-style`   | Present while the close transition runs                               |
| `data-placement`      | RAC placement string on positioned popups (`top`, `bottom start`, …)  |

`data-open` stays on the node through exit so `&[data-open]` selectors keep working. Native `<dialog>` overlays such as CommandPalette use `[open]` instead.

Recipes transition opacity (and a slight scale on dialogs/popovers) from `[data-starting-style]` / `[data-ending-style]`. Reduced motion skips the duration and unmounts immediately.

```css
.var-ui-popover[data-starting-style],
.var-ui-popover[data-ending-style] {
  opacity: 0;
}

.var-ui-popover {
  max-height: min(24rem, var(--var-ui-available-height));
  transform-origin: var(--var-ui-transform-origin, center);
}
```

### Exit before unmount

Closing does not remove the DOM until CSS animations on the popup (and backdrop, when wired) finish. `prefers-reduced-motion: reduce` unmounts immediately.

## Native dialogs (Dialog, AlertDialog, Drawer, MobileNav, LayoutPanel overlay)

`Dialog.Popup` is a native `<dialog>` opened with `showModal()`: the platform provides the top layer, the inert page, Escape and focus return. There is no backdrop element and no portal; the backdrop is `::backdrop` of the popup (its colour is `--var-ui-dialog-overlaybackground`). Style enter and exit with `[open]` and `@starting-style` instead of `data-starting-style` / `data-ending-style`:

```css
.var-ui-dialog__popup {
  opacity: 0;
  transition:
    opacity 150ms,
    overlay 150ms allow-discrete,
    display 150ms allow-discrete;
}
.var-ui-dialog__popup[open] {
  opacity: 1;
}
@starting-style {
  .var-ui-dialog__popup[open] {
    opacity: 0;
  }
}
```

The children stay mounted until the exit transition ends (the popup still gets `data-open` / `data-closed`). Scroll is locked by `html:has(dialog:modal) { overflow: hidden }`. Because the dialog renders in place, a `<button>` inside it submits an ancestor `<form>`, events bubble through its real ancestors, and inheritable properties (font, colour, `text-align`) flow in from them.

`Drawer.Popup`, `MobileNav` and the `LayoutPanel` `responsive="overlay"` panel are the same native `<dialog>`; they slide with `translate` from `data-placement` (`start` | `end` | `bottom`) or `data-side` (`start` | `end`), both following the writing direction.

Reasons: Escape is `escape-key`, a backdrop press (when `dismissable`) is `outside-press`, a `Close` part is `close-press`, the trigger is `trigger-press`, `requestClose()` or a back gesture is `imperative`. `details.cancel()` vetoes any of them. Chromium lets a page cancel Escape once per user activation: after that the dialog closes natively and the root re-opens it when `open` is still `true`.

## Positioner CSS variables

Set on positioned popups (Popover, Tooltip, HoverCard, Menu). Dialog centered overlays use `transform-origin: center`.

| Variable                    | Source                                                |
| --------------------------- | ----------------------------------------------------- |
| `--var-ui-available-height` | Viewport space remaining from the trigger             |
| `--var-ui-available-width`  | Remaining inline size from the trigger                |
| `--var-ui-transform-origin` | Opposite the placement side (`top` → `bottom center`) |
| `--var-ui-anchor-width`     | Trigger width, when the overlay has a trigger ref     |

Prefix is `--var-ui-` to match tokens. Values are `${px}px` strings.

## Change event details

Compound Dialog, Popover, Tooltip, HoverCard, Menu, Drawer, and AlertDialog call:

```ts
onOpenChange?: (open: boolean, details: OverlayChangeEventDetails) => void;
```

```ts
type OverlayOpenChangeReason =
  | 'trigger-press'
  | 'close-press'
  | 'escape-key'
  | 'outside-press'
  | 'imperative'
  | 'hover'
  | 'focus'
  | 'unknown';

type OverlayChangeEventDetails = {
  reason: OverlayOpenChangeReason;
  event: Event | null;
  cancel: () => void;
  isCanceled: boolean;
};
```

Reasons you can rely on: `escape-key`, `outside-press`, `trigger-press`, `close-press` (a `Close` part), `focus` (focus left the popup), `imperative` (your own code, e.g. a `setOpen` call), plus `hover` for hover overlays. Anything else is `unknown`. Roots derive the reason from native events, so they add no wrapper element to the DOM.

`cancel()` blocks the open-state update **when the overlay is uncontrolled**. If you pass `open`, `cancel()` is a no-op — ignore `open` in the parent instead.

```tsx
<Dialog.Root
  onOpenChange={(open, details) => {
    if (!open && details.reason === 'outside-press') {
      details.cancel();
      return;
    }
    setOpen(open);
  }}
>
  …
</Dialog.Root>
```

CommandPalette still uses `onOpenChange?: (open: boolean) => void`. It does spread presence attributes on the panel.

## Helpers

### `useOverlayPresence({ isOpen, reducedMotion?, getAnimatedElements })`

Returns `{ mounted, attrs }`. Drive `isOpen` from the requested open state. Keep React Aria’s `isOpen={presence.mounted}` so the node (and `getAnimations()`) exist through exit. Pass popup and backdrop elements to `getAnimatedElements`.

### `usePositionerVars({ placement, popupRef, triggerRef? })`

Returns `{ style }` with the variables above. Merge onto the popup root with `useLayer().style` when you also use `LayerProvider`.

### `useOverlayRoot({ open, defaultOpen, onOpenChange })`

The shared root hook behind every overlay: controlled/uncontrolled `open`, details-aware `onOpenChange`, presence, element tracking and reason derivation. See the source in `packages/react/src/overlays/useOverlayRoot.ts`.

### `createOverlayChangeDetails({ reason, event })`

Builds the `details` object with `cancel()` / `isCanceled`. Overlay components wrap RAC’s boolean `onOpenChange` with this.
