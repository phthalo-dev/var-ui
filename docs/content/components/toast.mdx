# Toast

For live notification queues without React, mount a `ToastRegion` and call the imperative
`toast` API from any client script. In React apps, use `ToastProvider` with `useToast()` or
`toast` from `@var-ui/react`. The imperative `toast()` needs a mounted `ToastProvider`: without one (or during SSR) it does nothing, returns `''`, and warns once in development. Changing `maxVisibleToasts` keeps toasts already on screen.

## Top layer and modal dialogs

The region is a native `popover="manual"` element: it is shown while the queue has toasts and
removed when the queue empties, with no z-index and no portal container option. The top layer
stacks by insertion order, so when a modal `<dialog>` opens (`[open]` changes) the region
re-promotes itself (`hidePopover(); showPopover()`) and stays above the backdrop, replaying its fade
in. Anything outside a modal dialog is inert while it is open, so toasts shown over a modal are
visible but **not clickable** (dismiss buttons included); their auto-dismiss timers keep running.
Prefer short, non-interactive toasts while a modal is open.

## Accessibility

Toasts render in a live region with appropriate status semantics. Dismiss controls
expose an accessible name and keyboard support via React Aria Components. `placement` accepts
`top-start`, `top-end`, `bottom-start` and `bottom-end` and follows the reading direction.
