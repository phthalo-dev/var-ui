# AlertDialog

Modal confirmation for important or destructive actions. `AlertDialog` is the compound Root: a `Dialog` with `role="alertdialog"` and backdrop dismissal off (`AlertDialog.Trigger`, `Popup`, `Header`, `Title`, `Description`, `Actions`, `Close`; the popup is a native `<dialog role="alertdialog">`, so there is no `Backdrop` part). The cancel/confirm arrangement is a recipe you copy, not a preset: confirm is just your button inside `AlertDialog.Close`, so Cancel and Escape never run it. The trigger must be a button — there is no `render` prop.

State attributes, exit animation, and `onOpenChange` details are documented in [Overlay lifecycle](/docs/overlay-lifecycle).

## Examples

### Default

Destructive confirms use `tone="danger"` and autofocus Cancel so Enter does not confirm by accident. `autoFocus` works on a `Button`; on a plain host element use the native `autofocus` attribute (React's `autoFocus` runs before the dialog is shown and does nothing there).

<Demo id="alert-dialog.default" />

### Confirm pattern

Non-destructive confirms use `tone="accent"` and `appearance="filled"`. Change the button labels to match the task. To confirm asynchronously, drop the confirm `AlertDialog.Close`, run your work in the button's `onClick`, then close with controlled `open`.

## Accessibility

Renders as a native modal `<dialog role="alertdialog">`; the rest of the page is inert. Destructive flows autofocus Cancel so Enter does not immediately confirm. Escape and the cancel button dismiss without calling `onConfirm`. Prefer a clear `title` and short `description` that name the irreversible consequence.
