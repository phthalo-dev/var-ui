# Table

Presentational semantic `<table>` for admin data grids. Use compound `Table.Header` / `Body` / `Row` / `Column` / `Cell` parts or a data-driven `columns` + `data` API.

### Bordered, with a minimum width

`bordered` frames the table with an outer border and rounded corners. `minWidth` sets the `<table>`'s minimum width (any CSS `min-width` value): when the container is narrower, the table scrolls horizontally inside its frame instead of squeezing the columns. `highlightOnHover` shades the row under the pointer.

<Demo id="table.bordered" />

## Styling the table

`className` and `style` go to the root, the horizontal scroller that frames the table. Give it a `maxHeight` to scroll rows under a `stickyHeader`. `ref` and every other native attribute (`aria-label`, `id`, `data-*`) go to the `<table>`, the same split as the form fields. To size the table from CSS instead of the prop, set `--var-ui-table-minwidth` on the root or in a theme.

## Accessibility

Renders a real `<table>`. Mark the identifying column with `rowHeader` (`scope="row"`). Prefer a `caption` (or external heading referenced with `aria-labelledby`) so the table has an accessible name. Sort chrome sets `aria-sort` when you wire `allowsSorting` / `onSortChange`.
